# 瀏覽器 Playtest 執行手冊

給**新的 Claude session** 用：使用者說「跑 playtest」時，照這份文件做。對使用者一律用**台灣華語（繁體中文）**、白話說明（使用者是程式新手）。

**Playtest 期間不改程式。** 只觀察、記錄、整理報告；要修哪個問題，等使用者指定。

---

## 0. 開始前檢查（任何一項失敗就停下，告訴使用者缺什麼）

| 項目 | 怎麼檢查 | 用途 |
|---|---|---|
| 網路：`lazyhk.com` | `curl -sS -o /dev/null -w "%{http_code}" https://lazyhk.com/` 應為 200 | 網站本身 |
| 網路：`codxdlpjcbydltuyutoy.supabase.co` | `curl -sS -o /dev/null -w "%{http_code}" https://codxdlpjcbydltuyutoy.supabase.co/auth/v1/health`（非 000 即可） | 瀏覽器登入與遊戲資料 |
| 網路：`api.vercel.com` | 同上方式，非 000 即可 | 讀 Vercel 後台 log |
| `PLAYTEST_EMAIL_1` / `PLAYTEST_PASSWORD_1` | `env \| cut -d= -f1 \| grep PLAYTEST` | **管理員帳號**，當房主（看得到任務目標面板、能唯讀查看劇本設定） |
| `PLAYTEST_EMAIL_2` / `PLAYTEST_PASSWORD_2` | 同上 | 第二位玩家（多人／分頭行動） |
| `VERCEL_TOKEN` | `env \| cut -d= -f1 \| grep VERCEL` | 讀部署紀錄與執行 log |

缺網路 → 請使用者到環境設定（session 標題列的雲端環境選單 → Edit → Network access → Allowed domains）加入該網域。
缺環境變數 → 請使用者在同一處加入，**開新 session 才會生效**。
**絕不**請使用者把密碼或金鑰貼在聊天裡；也絕不把它們印到終端、log、截圖或報告中（登入時只從環境變數讀取，截圖避開密碼欄位）。

## 1. 確認正式站跑的是哪個版本

Vercel 的 Production 是**手動推上去的**，很多「還沒修好」其實是新版本沒上線（見 `docs/ai-ops/06-lessons.md` 2026-10-08）。

- 用 `VERCEL_TOKEN` 呼叫 Vercel REST API（文件：https://vercel.com/docs/rest-api）列出 `target=production` 的最新部署，記下它的 git commit SHA。
- 對照 `git log --oneline`。報告第一行寫明「Production = `<sha>`」。
- 如果 Production 不含要驗證的修正，**先告訴使用者**，問要先推版還是照測。

## 2. 瀏覽器設定

- 用本機的 Playwright + Chromium（`PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers`，**不要**執行 `playwright install`）。腳本和輸出都放 scratchpad，不放進專案。
- 兩個獨立的 browser context：A = 管理員（房主），B = 第二帳號。
- 桌面 1440×900；另外用手機尺寸 390×844 抽查幾個畫面。
- 每個關鍵步驟截圖，檔名格式 `NN_簡短說明.jpg`；另外維護 `_log.txt`：`檔名 | 時間（UTC）| 房號 回合 | 輸入句子 | 觀察`。
- 登入頁：`/login`。開房：`/play/create-room`（或大廳流程）。房間頁：`/rooms/<id>`。

## 3. 先唯讀查看劇本設定（用管理員帳號）

打開劇本「**1404 室住戶守則**」的編輯頁，**只看不存**，記錄：

2. 所有「NPC 觸發事件」（哪個 NPC、條件、有沒有填地點、延遲、beat 內容）。
3. 「1404門口」的描述、第一次到達劇情（on_enter）、發現（discovers）。

這些是 Bug 8 尚未確認的資料，報告裡要列出來。地圖地點：1404客廳、1404門口、1404神位、1404廁所、1404東北角、1404房間、14樓走廊。

## 4. 測試項目

每項都要記錄：輸入句子、預期、實際、截圖、時間（UTC）、對應的 Vercel log。

### A. 最新修正（`efd97cb`）
1. **事件出場後不消失**：讓有固定位置的 NPC 觸發出場事件（依第 3 步查到的條件安排）。下一回合他應該仍在玩家所在地點，而且攻擊得到。log：`[npc:encounter] … placed NPC moved to …`。
2. **分頭行動不出現分身**：A、B 分開在不同地點，讓事件在其中一邊觸發。只有那一邊看得到該 NPC。
3. **事件不在錯的人身上觸發**：B 先走到事件指定的地點，接著輪到仍在別處的 A 行動。事件**不應**在 A 的回合觸發。
4. **NPC 受傷名字對應**：讓 GM 敘述中用簡稱（例如「婆婆」）造成傷害。log 應出現 `[injury] mapped GM NPC name "婆婆" → 陳婆婆`，不應出現第二個婆婆的血量。

### B. 先前修正的回歸檢查
5. 「打陳婆婆」「用刀刺陳婆婆」「給陳婆婆一拳」三種寫法都會擲骰進入戰鬥。物品欄沒有刀時，GM 不能變出刀。
6. 同一回合不會扣兩次血（系統扣血後 GM 不再另外扣）。log：`[injury] dropped … combat already settled`。
7. 玩家畫面看不到 NPC 的血量數字，只看到傷勢描述（輕傷／負傷／重傷）。
8. 輸入「我是神」之類的句子，不會觸發理智檢定。
9. 恐怖描寫出現時有文字特效。log：`[fx]`。
10. 創角配點：單項技能最多 80。
11. 抽卡後不用重新整理，新卡就出現在列表。
12. 發現卡（例如門口的守則卡）保留換行。
13. 回合分隔線為中文「── 第 N 回合 ──」。

### C. 已知未修，只記錄現況
14. Bug 6：在 1404神位 插香，看「在東北角補一炷香」會不會被勾選（管理員側欄）。log：`[objectives:check …] verdict completed=…`。
15. Bug 8：移動到 1404房間／1404門口後，GM 敘述的位置是否與側欄 📍 一致；敘述中走到別處時，📍 是否更新。

### D. 其他待討論項目（順手觀察即可）
物品是否進物品欄、用掉是否扣除（Bug 9）；大成功有沒有額外效果（Bug 10）；側欄地點按鈕只填入輸入框（Bug 17）；建議行動有沒有考慮技能值（Bug 18）；結束遊戲流程與故事回顧（Bug 21）；手機版遮擋、房間人數上限、沒調查員時的提示（Bug 23）；任務目標面板只對誰顯示。

## 5. Vercel log

- 用 Vercel REST API 讀 Production 部署在 playtest 時間範圍內的執行 log（runtime logs），用房號與時間對照。
- 要找的標籤：`[objectives:check`、`[npc:encounter]`、`[injury]`、`[attack:detect]`、`[scene:reaction]`、`[target:resolve]`、`[fx]`、`[choices:reject]`、`[scene-choices]`。
- 如果 API 讀不到 runtime logs，在報告中寫明「無法取得 log」，**不要**用猜測補上。

## 6. 安全與成本

- 只開測試用房間；**不**發佈、不送審、不修改任何劇本；管理員帳號只用來開房、看任務目標面板，以及唯讀查看劇本設定。
- 不修改後台設定、不刪除任何資料。
- 全部最多 40 回合；每場測完就正常結束遊戲。
- 遇到需要使用者決定的事（例如要不要推版）就停下來問。

## 7. 報告

- 格式沿用上一份報告：`# | 嚴重程度 | 問題 | 重現步驟（輸入句子）| 預期 vs 實際 | 截圖 | 時間（UTC）| log 證據`。
- 開頭寫：Production 版本、測了哪些房號、總回合數、哪些修正**確認有效**、哪些**仍有問題**。
- 嚴重程度：高（遊戲壞掉／資訊外洩）、中（規則錯誤）、低（外觀／文字）。
- 報告和截圖存 scratchpad，用 SendUserFile 傳給使用者（截圖可打包成 zip）。
- 最後用台灣華語簡短總結，列出建議下一個處理的問題，**等使用者指定後才改程式**。
