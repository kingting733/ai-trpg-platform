# 故事 → 劇本填表 Prompt（給創作者）

> **這是「手動填表」版本。** 若你想讓 AI 直接產出可匯入的 JSON（不用一格一格填），
> 請改用 **`/scenarios/prompt`** 頁面上的 Prompt —— 那份是從程式碼即時產生的，
> 永遠與最新格式同步，產出的 JSON 可直接貼進「建立劇本 → 貼上 JSON」完成匯入，
> 並會顯示「匯入報告」告訴你實際保留了什麼、有什麼被忽略。
> 產生器：`lib/ai/scenario-json-prompt.ts`。
>
> 這份文件仍然有用：當你想自己看著填、或想理解每個欄位的語意時。

有完整故事但覺得劇本編輯器欄位太多、不知道填什麼？把下面整段 Prompt 貼給任何
AI（ChatGPT / Claude / DeepSeek 都可以），最後貼上你的故事，AI 會輸出一份
「照著填就好」的填表指南，欄位順序與編輯器一一對應。

設計原則（改動這份 Prompt 時請保持）：
- **不編造**：AI 只能拆解故事已有的內容，缺的東西用 ❓ 問作者，不能自己補劇情。
- **對齊系統**：解鎖條件只允許平台實際支援的六種；地點三種狀態、證物取得方式、
  NPC 知識庫的語意都與編輯器/引擎一致。
- **規模上限**：地點 5–12、NPC 2–6、證物 4–10、目標 2–5、結局 2–4 —— 引擎與
  提示詞在這個規模最穩定。
- **多步驟目標警告**：目前目標判定不支援「重複 N 次」型目標，Prompt 內已註明
  要求改寫（對應系統 review issue #5；若日後支援了，把該行拿掉）。

---

```
你是一位 TRPG 劇本編輯助手。我有一個完整的故事，想把它填入一個「AI 主持的克蘇魯風跑團平台」。這個平台的伺服器會自動管理地點、證物、NPC 情報與結局，所以我需要你把我的故事拆解成下面這些欄位。

【最重要的規則】
1. 只根據我的故事內容拆解，不要自行編造新情節、新角色、新地點。故事沒寫清楚的地方，用「❓建議：…」標出來讓我自己決定。
2. 全部用繁體中文輸出。
3. 規模控制：地點 5–12 個、NPC 2–6 位、證物 4–10 件、目標 2–5 個、結局 2–4 個。故事太長就挑主線。

【平台的解鎖條件寫法】（後面多處會用到，只能用這六種）
- 拿到證物「X」
- 去過地點「X」
- 累積 N 件帶有「某標籤」的證物
- 到第 N 回合
- 進入地點「X」後過 N 回合
- 完成目標「X」

請依序輸出以下十個部分：

① 基本資料
- 劇本標題／類型（恐怖、懸疑…）／建議人數／預計時長／一句話簡介（給玩家看，不可爆雷）

② 開場場景（Opening Scene）
- 100–200 字，把玩家們放進故事的第一幕。只鋪氣氛與處境，不透露任何謎底。

③ 地圖（地點系統）
先列「區域」（一個區域 = 一個大空間，例如一層樓、一間屋、一條街）：
| 區域名 | 入口地點 | 區域內地點是否互通 |
再列每個「地點」：
| 地點名 | 所屬區域 | 初始狀態（開放／已知但鎖定／隱藏） | 解鎖條件（用上面六種寫法） | 進入後自動發現哪些地點 | GM場景備註（玩家看不到） | 鎖定時的拒絕描述 |
最後列「路徑」：哪個地點連到哪個地點，單向還是雙向（同區域內互通的不用列）。
※ 大部分地點應該是「開放」；只有需要鑰匙／條件的用「已知但鎖定」，需要被發現的祕密處用「隱藏」。

④ 證物（線索物品）
| 證物名 | 放在哪個地點 | 取得方式（一句話，例：搜查書桌／撬開保險箱） | 標籤（用於「累積N件」條件，可留空） | 取得後給玩家看的揭示文字 |
※ 取得方式寫「搜查…」的，玩家搜索成功就能拿到；寫特定動作（如「破壞電腦」）的，必須做那個動作才拿到。

⑤ NPC
每位 NPC 輸出：
- 名字／身分
- 性格（1–2 句，GM 扮演用）
- 目標與祕密（1–2 句，玩家不可直接得知）
- 初始態度：友善／中立／敵對
- 所在地點（在哪個地點出沒；會移動就寫「第N回合後移到X」）
- 情報（知識庫）：這位 NPC 知道什麼？每條寫成：
  | 話題（玩家問到什麼會觸發） | 內容（NPC 會說出的資訊） | 解鎖條件（可留空=一問就答） |

⑥ NPC 觸發事件（可選）
| 觸發條件 | 哪位 NPC | 發生什麼（給 GM 的一句指示） |

⑦ 任務目標
| 目標內容 | 全隊共同 或 每人各自 | 必要 或 加分 |
※ 每個目標必須是「做一件可判定的事」。⚠ 避免「重複 N 次」型目標（例如「在四個角落各放一次米」），目前系統對多步驟目標支援不佳，請改寫成一次性動作。

⑧ 結局
| 結局名 | 類型（勝利／中立／失敗） | 達成條件（用六種寫法組合） | 結局概要（2–3 句） |

⑨ 失敗條件與回合上限
- 什麼情況全隊直接失敗？建議回合上限是幾回合？

⑩ GM 備註（Pacing Notes）
- 3–6 條給 AI 主持人的節奏提示：什麼時候該升溫、哪個轉折在哪個階段揭開、絕不能提前洩漏什麼。

輸出完後，最後請列出「❓需要我決定的事項」清單（你拆解時拿不準的所有地方），一次問完。

以下是我的故事：
【把你的故事貼在這裡】
```

## 填表時的對照

| Prompt 輸出 | 編輯器位置 |
|---|---|
| ① 基本資料 | 劇本基本欄位（標題/類型/人數/時長/簡介） |
| ② 開場場景 | 世界觀 → Opening Scene |
| ③ 地圖 | 🗺 地點系統（地圖模式：先建區域→地點→畫路徑） |
| ④ 證物 | 各地點內的「此地點可取得的證物」 |
| ⑤ NPC + 情報 | NPC 名單 + 每位的 情報/知識 區塊；所在地點填「NPC 位置設定」 |
| ⑥ 觸發事件 | ⚡ NPC 觸發事件 |
| ⑦ 目標 | 任務目標編輯器 |
| ⑧ 結局 | 🎭 多重結局 |
| ⑨ 失敗條件/回合上限 | 失敗條件 + Failure Turn Limit |
| ⑩ GM 備註 | GM Notes |
| 原始故事全文 | Source Document（原文照貼，AI 主持人會讀） |
