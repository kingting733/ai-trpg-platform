# 引擎限制——寫故事時就要守的規則

這份文件是給「寫故事的人」看的，不是給填 JSON 的人。每一條都說明**為什麼**，因為原因懂了，沒列到的情況你也判斷得出來。規則來源是程式碼（`lib/game/*`、`app/api/gm/respond/route.ts`）與 playtest 紀錄；程式改了這份要跟著改。

## 一、故事是一張地圖，不是一條時間線

玩家一次只站在一個地點，只能對該地點的東西行動。伺服器記住每個人在哪裡；AI 主持人只能描述那個地點。所以：

- **每個祕密都要「藏在某個地點的某個東西裡，要做一個具體動作才拿得到」**，或是「某個 NPC 在某個條件下會說」。沒有地點、沒有動作的真相，在遊戲裡等於不存在。
  - ✗「調查員發現死者其實是被滅口的。」
  - ✓「死亡證明的副本壓在玄關鞋櫃最底層，要把鞋子全搬開才看得到。」
- **起點只有一個**。開場時只有一個地點是開放的；其他地點要嘛「已知但進不去」（寫清楚為什麼進不去、什麼條件才開），要嘛「隱藏」（玩家到了某處才會發現它存在）。一開始就開放好幾個地點，等於有好幾個起點，開場就失去意義。
  - 例外：用「地圖模式」（只能沿路徑走）時，起點旁邊直接相連的地點可以一開始就開放，因為玩家還是得從起點走過去。自由移動模式下就只能開一個。
- **每個地點都要有事可做**：至少一件證物、或一位 NPC、或它是通往別處的必經之路。到了什麼都拿不到的地點是冷場。
- 建議規模：地點 5–12、區域（一層樓／一棟屋）1–4。引擎上限是 40 個地點、12 個區域，但到那個規模 AI 會開始搞混。

### 地點能用的解鎖條件（只有這六種，其他寫法會被忽略）
1. 拿到證物「X」
2. 去過地點「X」
3. 累積 N 件帶有「某標籤」的證物
4. 到第 N 回合
5. 進入地點「X」後過 N 回合
6. 完成目標「X」

寫故事時把「門為什麼開」對到這六種之一。「說服房東」不是條件——要改成「拿到房東交出的鑰匙（證物）」。

- 條件可以**組合**：同時滿足（且）與任一成立（或）都可以，例如「（拿到地形圖）或（到第 8 回合）」。這套條件同時用在地點解鎖、NPC 位置、出場事件、結局四個地方。
- 這裡的「回合」是**每位玩家各行動一次**，所有人輪完一圈才加 1（見第六節）。
- 地點**只能打開，不能再鎖上**。故事裡「門關上了」「走廊塌了」可以寫成描述，但劇情不能依賴「回不去」。
- 沒有「否定」條件：不能寫「沒拿到某物」「沒去過某地」。唯一的例外是結局的「NPC X 存活」。

## 二、證物（線索物品）

每件證物寫四樣東西：**在哪個地點、要做什麼才拿到、拿到時看到什麼、（可選）標籤**。

- **拿證物一定要擲骰成功**。玩家做了對的動作、而且那次檢定成功，伺服器才會給。所以「這條線索不靠骰子」只有三種寫法：地點第一次進入時的描述（所有人到了就看到）、NPC 出場事件（他自己找上門說出來）、到第 N 回合才打開的地點本身。解法和終局工具的三個來源裡，至少要有一個是這三種之一。
- **NPC 交給玩家的東西**：證物沒有「NPC 答應了才給」的欄位。寫成那位 NPC 所在地點的證物，取得方式寫成一個具體動作（「把族譜拿給水生伯看」），再配一條不靠他的慢路徑（第 N 回合門被風吹開）。他願不願意，只能靠情報條件約束 AI。
- **數量**：每個有內容的地點 1–3 件。一般 4–10 件；4 人、2 小時以上可以到 15 件左右，但每件都要有用（指向下一步，或是解法的來源之一）。

- 「要做什麼」是玩家會打出來的動詞短語：「翻找鞋櫃」「撬開保險箱」「搜查書桌」。寫「搜查／翻查…」的，玩家任何搜索成功就拿得到；寫特定動作的（「砸開神像」）就一定要做那個動作。這句話會被程式拿去比對玩家輸入，太文學的句子比不到。
- 「看到什麼」只寫**所見**：外觀、狀態、上面寫的字。不寫它證明了什麼、誰做的、NPC 看到會怎樣。結論留給玩家推，真相放在故事的「真相」段。
- 標籤用在「累積 N 件」的條件（例如三件「儀式」標籤的證物才開啟地下室）。
- 玩家拿到的證物在畫面上只顯示成中性的「📦 物品」，沒有「線索 3/7」之類的計數。所以**不要靠「玩家知道自己找到幾個線索」來推進**。

## 三、NPC

NPC 是「有鎖的情報庫」加「有立場的人」，不是自由發揮的角色。每位寫：

- **性格**（1–2 句，AI 扮演用）、**目的與祕密**（玩家不能直接得知）。
- **在什麼條件下會做什麼**：「答應幫忙」「交出鑰匙」「崩潰承認」都要有條件（拿出某證物對質、到第 N 回合、先去過某地）。沒有條件，AI 會在骰子第一次成功時就全給。
- **情報**：一條一條列，「玩家問到什麼 → 他說什麼 → 要先滿足什麼」。至少一條要有條件；全部一問就答的 NPC，第一輪就被問光。
- **態度**三選一：友善（從不攻擊，被打也不還手）／中立（被攻擊才反擊，預設）／敵對（一出場就攻擊整隊）。被攻擊時，同一地點的其他 NPC 會有反應（目擊），所以「當眾動手」是有後果的。
- **平常在哪**：寫「在 X」或「第 N 回合後移到 Y」「拿到某物後移到 Y」。可以排好幾段，最後一段成立的算數，所以 NPC 能照日程移動（例如整點都到宴會廳集合）。
  - **沒寫位置的 NPC 會「到處都在」**——每個地點都看得到他、打得到他。分頭行動時他會同時出現在兩個場景。重要 NPC 一定要給位置。
- **出場事件**（可選）：「某條件成立時，這個 NPC 找上隊伍，發生什麼」。規則：
  - 事件只觸發**一次**。
  - 寫了地點就等玩家到那裡才觸發；**沒寫地點 = 條件一成立就立刻出現，不管隊伍在哪**。這只適合電話、託夢、鬼魂這類真的能隨時找上門的情況。真人 NPC 一律寫地點，需要的話加「延後 N 回合」。
  - 事件觸發時，伺服器會把這個 NPC **移到觸發事件那位玩家所在的地點**，之後他留在那裡（直到故事排定的下一次移動）。所以「他出現了」是真的出現，可以對話、可以攻擊；敵對 NPC 當回合就可能動手。
- **敵對 NPC 和玩家在同一地點就會出手**。想要「遠處看得到、靠近就消失」的追獵者，白天的目擊寫成地點描述或證物，本體只靠一次出場事件登場。
- **沒有「劇情殺」**：NPC 只會在戰鬥或受傷時死。故事裡「玩家趕到時他已經死了」的人，不要做成 NPC，做成那個地點的證物（屍體、遺物）。同理，只在電話裡、信裡、回憶裡出現的人，做成證物（動作：「打電話給某人」「讀信」）。
- **態度不會換邊**：友善／中立／敵對是固定的。故事裡「他依玩家的選擇變成敵人或盟友」，要改寫成條件情報（拿出某物他才說實話）加上結局條件（誰死、誰活），不要設計成戰鬥陣營翻轉。
- NPC 血量：故事裡沒寫就是 10。想讓某個 NPC 很難打死就寫出來。
- **一開始哪裡都不在**：給 NPC 一條「還沒成立」的位置設定（例如「拿到地形圖後在洞口」），在條件成立前他哪裡都不在、誰也碰不到。怪物、追獵者就這樣藏起來，再用出場事件把他帶到玩家身邊。**不要什麼位置都不寫**，那會變成到處都在。
- 不說話的怪物不需要情報（轉換器會給一條「沒有情報」的警告，可以忽略）。
- 建議 2–6 位。少於兩位沒得盤問，多於六位 AI 記不住立場。

## 四、目標（任務目標）

詳細規則在 `docs/creator-guide/objectives.md`。這裡只列會讓故事壞掉的：

- **一條目標 = 一件 AI 主持人會在敘事裡明寫出來的事**。判定器每回合只讀「玩家做了什麼」和「GM 寫了什麼」，不讀玩家心裡想什麼。
  - ✗「理解宅子的真相」「與船長談成合作」
  - ✓「從壁爐暗格取出燒到一半的名單」「船長親口答應今晚開船」
- **一條只放一件事**。有先後 → 拆兩條；有「或」 → 改成一件事，分支放括號。
- **用正式名字**。NPC、證物、地點的名字要跟故事其他地方一字不差。
- **全隊共有**。任何一人做到就算整隊做到；沒有「每人各自」，也沒有祕密的個人目標。
- **「交給誰」只能用目標表達**：引擎沒有「交出物品」的條件。結局取決於把東西交給誰時，寫成目標（「把金屬桿沉進海灣」「把印交到守護者手上」），再用結局條件引用那條目標。
- **目標判定器看不到玩家的位置**。兩條目標如果只差在地點（「在北窗點蠟燭」vs「在南窗點蠟燭」），判定器會混淆。用不同的物件或動作區分（「在北窗點蠟燭」vs「在門檻撒鹽」），或合成一條多步驟目標。
- **做了會失敗的動作不要列進目標**。把「喝下那杯酒」列在目標裡，而喝下去會直接進失敗結局——玩家照著目標做反而輸，這是陷阱。失敗條件寫在結局，不寫在目標。
- **關鍵目標要有門檻**。至少一條必要目標要卡在「需要檢定才拿得到的證物」或「需要先解鎖的地點」後面。否則玩家照著目標念一遍，幾回合不用擲骰就通關。
- 多步驟目標可以（「在四個角落各放一撮米」），判定器會記錄進度；但每一步都要是具體事件。
- **每條目標都要被用到**：被某個結局、地點解鎖、NPC 位置、NPC 情報或出場事件當成條件。只出現在結局文字裡、沒有被當成條件的目標，轉換時會被刪掉。
- 建議 2–5 條，超過三條就標一些為「加分」。

## 五、結局

結局是**唯一**能結束遊戲的東西。沒寫結局，故事就只有「全員死亡」會結束。

- 每個結局寫：名字、類型（勝利／失敗／中性）、**觸發條件**、之後發生什麼（給 AI 寫結尾畫面的指示，30 字以上，寫每個角色的下場）。
- 條件只能用：上面六種地點條件 + 「NPC X 死亡」「NPC X 存活」「完成目標 X」。可以 AND、可以 OR。
- 沒寫勝利結局時，系統會自動用「所有必要目標完成」當勝利。寫了就以你的為準。
- **時鐘到期的失敗，自己寫一個結局**：條件寫「到第 N 回合」，結尾畫面才會是你寫的。不要依賴其他「回合上限」設定。
- **簡介和開場也不能指錯方向**：給玩家看的簡介、開場敘述裡說「撐到天亮」「完成委託」，而那件事其實是失敗結局的條件，玩家就會照著走向失敗。玩家被告知的目標，至少要對應一個不是失敗的結局。
- **「去過某地點」也能觸發結局**，適合逃脫型（「走出林間小路」＝逃離）。
- 失敗結局會讓角色無法成長（卡片經驗），所以「失敗」要留給真正的失敗；「活著逃出但沒解決」用中性。
- CoC 的好結局通常是「活下來／封印／付出代價」，不是全贏。2–4 個結局，而且要差得夠大——玩家的取捨真的改變誰的下場。
- **描述不能洩題**：列表上玩家看得到的簡介只寫處境，不寫轉折。

## 六、回合、戰鬥、恐怖——引擎已經在做的事

這些不用你設計，但寫的時候要知道：

- **回合**：一回合 = **每位玩家各行動一次**，全員輪完一圈才進下一回合。所以「第 10 回合」對 4 人團是第 30 多個行動，對 2 人團是第 20 個左右。所有「到第 N 回合」「進入某地後過 N 回合」都用這個算。粗估每個行動約 1 分鐘（打字加 AI 回覆），4 人玩 2 小時大約 25–30 回合；排時鐘時用「每位玩家有幾個行動」思考，不要用總行動數。內容量要配得上，不要五個地點只有兩件事。
- **同一地點的人看到同樣的東西**：沒有只給某位玩家看的私密資訊、沒有暗骰、不能依某人的屬性（例如理智最低的人）挑人。「只有某人看得見」要改成「拿到某證物（例如牛眼淚）後，全隊都看得見」。
- **檢定沒有難度分級**：困難、極難、大成功目前都沒有額外效果。原作的「困難檢定才拿得到」改成「普通成功＋前置條件」。
- **角色卡會跨團延續**：失敗結局的角色不能成長。「其實你們早就死了」「變成怨靈、卡片作廢」這類設定和卡片系統衝突，要在簡介說明，或改寫成不影響角色卡的版本。
- **擲骰**：玩家的行動會對應技能檢定（偵查、心理學、搏鬥…）。你寫「要做什麼才拿到」時，動作本身會決定用哪個技能。
- **戰鬥**：「打 X」「用刀刺 X」「給 X 一拳」都會進入戰鬥擲骰。玩家手上沒有的武器不會憑空出現——想讓玩家有武器，就放一件武器證物。NPC 被打會反擊（中立）或不反擊（友善），旁邊的 NPC 會有反應。
- **理智檢定**：靠 AI 敘述裡的關鍵字觸發，分等級：
  - 明顯：屍體、血跡、腐爛、慘叫……
  - 強烈：怪物、觸手、異形、儀式現場……
  - 核心：邪神、血祭、獻祭、不可理解、異界……
  所以升溫階梯的每一階，要讓 GM **有畫面可寫**：第一階只有違和（聲音、氣味、位置不對的東西），中段出現目擊（影子、屍體、符號），後段才是接觸與不可理解。一開場就「邪神」，後面沒得升。
- **恐怖文字特效**：理智檢定發生的回合，畫面會對該段文字加特效。不用你管。
- **分頭行動**：玩家可以各走各的；每個場景只描述在場的人。NPC 位置因此更重要（見第三節）。
- **物品**：隊伍共用一個軟性物品欄；AI 可以提議「拿到／用掉」，伺服器核准。目前「敘事裡撿到的東西有時沒進物品欄」是已知問題，所以**重要的東西都做成證物**，不要靠 AI 臨場給。

## 七、寫完後的檢查表

逐條過，一條不過就回去改：

**地圖**
- [ ] 只有一個起點；其他地點都寫了「怎麼開」或「怎麼被發現」
- [ ] 每個地點至少一件證物、或一位 NPC、或是必經之路
- [ ] 從起點走得到每一個地點（鎖的條件在遊戲裡拿得到）

**線索**
- [ ] 每個關鍵真相至少三條路拿到（不同地點／NPC／動作）
- [ ] 每件證物有：地點、玩家會打出來的動作、只寫所見的描述
- [ ] 沒有任何一步要玩家「猜到特定句子」才能前進

**NPC**
- [ ] 每位 NPC 有位置（或明確是「隨時能找上門」的類型）
- [ ] 每位 NPC 至少一條情報有條件；「答應／交出／承認」都寫了條件（不說話的怪物除外）
- [ ] 怪物、追獵者用「還沒成立的位置」藏起來，不是什麼位置都不寫
- [ ] 出場事件：真人有地點；觸發後他留在那裡合不合理

**目標**
- [ ] 每條是 GM 會明寫的事件，一條一件事，名字一字不差
- [ ] 沒有兩條只差在地點
- [ ] 沒有「做了會失敗」的動作
- [ ] 至少一條必要目標卡在檢定或解鎖後面

**結局**
- [ ] 2–4 個，條件只用支援的寫法，彼此差得夠大
- [ ] 每條目標都被某個條件引用；簡介和開場說的目標不是失敗條件
- [ ] 解法的三個來源裡，至少一個不用擲骰（第一次進入的描述／出場事件／回合開門）
- [ ] 有時鐘（某回合會發生的事，或回合上限），玩家不能無限嘗試
- [ ] 簡介不洩題；真相段寫完整

**節奏**
- [ ] 回合數配得上內容：探索、對抗、收尾各有份量
- [ ] 升溫階梯四階都有畫面，不是一開始就最大

## 八、已知的引擎坑（寫故事時避開，不要等它修）

| 問題 | 影響 | 怎麼避 |
|---|---|---|
| 目標判定器看不到位置 | 只差地點的目標會互相誤判 | 用物件／動作區分 |
| 敘事裡的移動不會更新系統位置 | GM 寫「走到角落」，系統仍在原地 | 把重要的「角落」做成真正的地點 |
| 敘事裡撿到的東西不一定進物品欄 | 用掉時扣不到 | 重要物品做成證物 |
